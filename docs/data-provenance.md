# Data provenance policy

CyberTrace uses two deliberately separate data classes.

## Real data

The initial real dataset is the pinned MITRE ATT&CK Enterprise v19.2 STIX 2.1 release described in `data/source-manifest.json`. Imported groups, software, techniques, and relationships must retain source identifiers and dataset metadata. A node or relationship is marked real only when the source dataset explicitly supports that record or link.

Required real-record fields where applicable:

- `source = "MITRE ATT&CK"`
- `source_id` containing the ATT&CK external ID or STIX ID
- `source_url`
- `dataset_version`
- `retrieved_at`
- `is_synthetic = false`

## Synthetic data

Synthetic organizations and infrastructure exist only to provide complete, repeatable demonstration paths. They are generated by project code rather than claimed to come from MITRE or another real threat feed.

Required synthetic-record fields:

- `source = "Synthetic"`
- `is_synthetic = true`
- `generator_version`
- `generation_seed`

Only RFC 5737 documentation IP ranges and IANA-reserved example domains may be generated. Synthetic relationships must carry the same provenance distinction as synthetic nodes.

## Mixed paths

A displayed investigation path may contain both real and synthetic elements, but the UI and API must expose provenance for every node and relationship. A mixed path must never be presented as a wholly documented real-world incident chain.
